# ADR-013: Single Permanent Shared Transport Draft

- **Status:** Accepted
- **Date:** 2026-11-21
- **Supersedes in part:** ADR-011 named and expiring draft wording.

## Decision

The Transport Data module has exactly one permanent shared working draft.
Authorized users open the same draft, save its complete snapshot, and later
publish it. Publishing preserves the draft and creates a new immutable
published snapshot for public reads and audit/recovery. The draft is exempt
from lifecycle expiry/deletion.

Schedule rows remain route-level. The Public PWA groups buses with the same
route and next departure time into one row and displays their identifiers
under the route code.

Within the approved single FastAPI worker, Save Draft and Publish are guarded
by one FIFO async gate. Each executing request receives a process-local,
temporary increasing numeric operation order. PostgreSQL transactions remain
the persistence integrity boundary.

## Consequences

Create/search draft controls and endpoints are replaced by Open Draft. A
publish warning is produced only for routes with no recurring schedule entry;
accepting it publishes. A permanent shared draft does not require a rebase to
publish: each publication snapshots its most recently saved content. Concurrent
stale saves continue to receive `409` after their turn, preventing silent
overwrites.
