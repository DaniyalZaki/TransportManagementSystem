# ADR-005: Use a Shared Publishing Pipeline for Urgent and Routine Announcements

**Status:** Accepted
**Current profile:** Announcement publication remains direct and shared; ADR-011 narrows audit logging so announcement publications do not create audit records.
**Date:** 2026-11-12
**Project:** University Transport Information Portal

## Related drivers

- **ASR-02 — Urgent-change propagation:** Confirmed urgent operational changes must be live no later than 1 minute after confirmation.

## Context

The portal supports routine announcements as well as urgent operational notices. Confirmed urgent changes must become live within one minute.

The architecture must determine whether urgent announcements need a separate, dedicated publishing pathway or whether they can use the same pipeline as routine announcements.

The Announcement module already supports direct publishing without a draft step. Publishing an announcement also writes an audit entry and invalidates relevant cache entries synchronously.

## Options considered

| Option | Advantages | Disadvantages |
|---|---|---|
| Dedicated fast path or queue for urgent announcements | Provides a separate pathway for urgent publishing | Adds complexity for a narrow case |
| Shared pipeline for all publishing | Keeps the publishing architecture simpler; announcements already publish directly without a draft step | Urgent and routine announcements may contend for the same pipeline |

## Decision

Use a **shared publishing pipeline for urgent and routine announcements**.

- Urgent and routine announcements use the same publishing workflow.
- Announcements are published directly, without a draft step.
- Publishing writes an audit entry and invalidates relevant cache entries synchronously.
- Urgent announcements must complete within the one-minute bound.
- Revisit the decision only if contention is observed.

## Rationale

A dedicated fast path or queue would add complexity for a narrow case. Announcements already use direct publishing without a draft step, making their writes lightweight.

The shared pipeline therefore avoids introducing a separate urgent publishing mechanism while retaining the required one-minute completion target.

The decision can be revisited if contention is observed.

## Consequences

### Positive
- Urgent and routine announcements use one publishing workflow.
- No dedicated urgent queue or fast-path mechanism is required.
- Direct publishing avoids an additional draft step for announcements.
- Publishing retains the audit-writing and synchronous cache-invalidation behavior.

### Negative
- Urgent and routine announcements share the same pipeline.
- Both types of publishing may contend for shared resources.

### Risks
- Contention in the shared pipeline could prevent urgent announcements from meeting the one-minute bound.

### Revisit when
- Contention is observed in the shared publishing pipeline.

## Verification

- Verify that urgent and routine announcements use the same publishing pipeline.
- Verify that announcements publish directly without a draft step.
- Confirm that publishing writes an audit entry.
- Confirm that relevant cache entries are invalidated synchronously.
- Measure urgent announcement publishing completion against the one-minute bound.
- Observe pipeline contention and revisit the decision if it occurs.
