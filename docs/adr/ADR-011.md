# ADR-011: Approved Implementation and Lifecycle Profile

- **Status:** Accepted
- **Date:** 2026-11-18
- **Supersedes in part:** ADR-003, ADR-004, ADR-006, ADR-007, ADR-008, ADR-009, and ADR-010 where their earlier language conflicts with this decision.

## Decision

The portal uses Python/FastAPI, handwritten asynchronous PostgreSQL SQL and
migrations, PostgreSQL, separate Next.js/TypeScript clients, Tailwind CSS,
Workbox, Pytest, and Cypress. The backend runs as one FastAPI worker and uses
an in-process read cache.

Supabase Auth is self-hosted on the PostgreSQL deployment. The backend owns
the Supabase-user-to-role mapping in PostgreSQL and validates active JWTs
locally. Only Transport Management manages privileged accounts. The first
Transport Management account is manually provisioned in Supabase. Email and
password are used; Supabase defaults apply; MFA is not required; active tokens
remain valid until expiry after account deactivation.

Transport edits are collected in named change sets. Publishing is atomic,
stale drafts require rebase, and recovery restores a whole published change
set for 30 days. Drafts expire after 30 days. Retired published records remain
recoverable for 30 days and are then physically deleted. Full and partial
date-specific schedule overrides are supported; partial overrides match Route,
Bus, and time, so time changes are remove/add operations. ADR-012 defines the
current route-level recurring schedule representation and fixed directions.

The Audit module records only transport-publication events (publisher and
time) for 30 days. It does not record edits, announcements, prior announcement
versions, or login/logout events.

Feedback uses SMTP, normalized-content duplicate detection, 30-day retention,
and retries at 1, 5, and 30 minutes. Immediate failure shows an error; later
retry success is not reported. The public PWA uses Workbox/IndexedDB/Cache
Storage, caches announcements but not active urgent banners, and synchronizes
only while open, on reconnection, or manually.

Production hosting and RTO/RPO implementation are deferred. Local development
services are authorized; production release work must choose and verify them.

## Consequences

This decision narrows the previous audit scope, makes Transport Management the
sole account-management authority, and constrains cache deployment to one
FastAPI worker. Any future multi-worker deployment needs a reviewed shared
cache decision. The PRD and architecture are updated to reflect this profile.
