# Encountered Issues

This log records verified implementation and local-development issues encountered
while delivering Slice 2. It distinguishes product-code fixes from machine-local
environment problems.

| Slice | Issue | Summary |
|---|---|---|
| S2 | Incomplete change-set workflow | The initial Slice 2 work only created, validated, rebased, and published drafts; draft updates, publication history, recovery, retention cleanup, and transaction-joining Audit writes were added to complete the slice. |
| S2 | Draft-create endpoint returned 404 | The admin application was calling the correct URL, but an old FastAPI process was still running and its OpenAPI document did not include the Slice 2 router. Restarting the backend with current source restored the route; unauthenticated requests now correctly return `401`. |
| S2 | Tailwind directives were not compiled | The admin app lacked an effective monorepo PostCSS configuration, so the browser received literal `@tailwind` directives and TSX utility classes had no effect. Root and app PostCSS configuration now compile Tailwind utilities. |
| S2 | Next.js cache failures under OneDrive | Stale `.next` cache entries caused `EINVAL`/`readlink` errors and a missing generated chunk, leading to HTTP 500 responses and failed browser tests. Restarting after moving the regenerable admin cache aside restored the admin server; the cache remains an environment risk. |
| S2 | Cypress browser verification blocked | Cypress could not load the public PWA because the stale local Next.js server returned HTTP 500 before test execution. Backend, lint, type-check, and production-build checks succeeded; rerun Cypress after rebuilding its `.next` cache. |
| S2 | Local Git credential helper could not push | Git Credential Manager waited for unavailable interactive credentials and non-interactive push reported no password. The GitHub connector created and advanced the remote branch instead. |
| S2 | Publication-history database migration was not applied | The local database lacked the Audit publication table created by migration `0003`, so signed-in publication-history requests could not complete. Applying the migration restores the required Slice 2 persistence schema. |
| S2 | Publication-history request showed a raw network error | The admin history action did not catch fetch failures or show non-OK responses. It now explains authentication, HTTP, and backend-connectivity failures in the existing status notice. |
| S2 | Supabase login tokens omitted their issuer claim | The local GoTrue compose service did not configure `GOTRUE_JWT_ISSUER`, while the backend correctly requires issuer validation. Configuring the approved local issuer restores authenticated draft and history requests without weakening JWT checks. |
| S2 | Schedule editor dropped paired selections | The schedule form merged route and bus selections through a stale closure, leaving draft state incomplete even when the controls looked selected. Functional state updates now preserve both values before a departure is added. |
| S2 | Public PWA Tailwind compilation failed | The Public PWA lacked its own PostCSS configuration, so Next.js failed while compiling global styles. Adding the app-local Tailwind configuration restores the public application and its Cypress suite. |
| S6 | No server-side graceful-degradation plan for public-PWA overload | The architecture specified a 24-hour client cache and service-outage display but did not protect the single API worker or PostgreSQL from excess public traffic. ADR-014 now requires a health-checked deployment edge with bounded queues/timeouts, public-read admission limits, and prompt overload responses; the PWA retains its existing labelled cache/unavailable fallback. |
| S4 | Local feedback requests failed with `NetworkError` | The backend accepted only `localhost` origins while the local PWA was also served at `127.0.0.1`; browser CORS rejected the request. Both standard local origins are now allowed. |
| S4 | Local API default had ambiguous `localhost` resolution | The FastAPI development process was bound to IPv4 only, while `localhost` resolved to IPv6 and IPv4. The Public PWA now defaults locally to `http://127.0.0.1:8000`; production continues to use `NEXT_PUBLIC_API_BASE_URL`. |
| S4 | SMTP settings were unavailable to an already-running backend | `.env` values were not inherited by the process started before configuration. Relaunching the local backend with those environment variables restored its SMTP configuration; Gmail TLS authentication was verified without sending a message. |
